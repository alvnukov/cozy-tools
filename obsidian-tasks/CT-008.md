## Body

## What to build
Turn the reviewed module into a versioned public dependency after all release-blocking API and safety work lands. Define the stable package map and compatibility promises, publish release notes and a SemVer tag, and provide downstream migration instructions without changing cozyphi as part of this task.

## Blocked by
CT-002 — Add injection-safe command value channels.
CT-003 — Make command policy host-neutral and instance-scoped.
CT-004 — Make CommitOwned transactional across processes.
CT-005 — Capture ordered combined output as a bounded tail.
CT-006 — Bound and align command history limits.
CT-007 — Unify file-family behavior behind one rooted mechanism.

## Acceptance Criteria

- Stable and compatibility-only packages are explicitly identified, documented, and covered by an API compatibility policy.
- All release-blocking tasks are complete and no temporary host-specific API remains in the stable surface.
- Test, race, vet, lint, security, vulnerability, dependency, gopls, and supported-platform build gates are green.
- Release notes describe migration from the local replace and identify intentionally deferred cozyphi integration.
- A SemVer tag is published and downstream consumers have a concrete replace-removal migration procedure.

## Verification Plan

1. Run the complete verification matrix from the review on a clean worktree.
2. Compare the exported API against the approved package map.
3. Verify module consumption from a temporary downstream module without a local replace.
4. Verify the release tag and release notes reference the exact commit.
