## Body

## What to build
Define and publish the command-family trust model so callers can distinguish structured data channels, raw shell source, advisory policy guards, and actual security boundaries. The contract must make clear that textual shell scanning is UX/policy guidance rather than a sandbox, and must decide the migration contract used by the safe-value and host-policy follow-ups.

## Blocked by
None — can start immediately.

## Acceptance Criteria

- Public documentation identifies trusted and untrusted inputs and states the security guarantees of shell execution, policy guards, secret masking, and filesystem containment.
- No public documentation or diagnostic implies that textual forbidden-command scanning is a capability sandbox.
- The chosen compatibility and deprecation contract for raw shell interpolation is explicit enough for the safe-value task to implement without another API decision.
- Contract tests and examples cover the supported boundary without encoding host-specific product behavior.

## Verification Plan

1. Run focused command and variable package tests.
2. Run package documentation and exported-API checks.
3. Run the full Go test suite.
