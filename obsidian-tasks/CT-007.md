## Body

## What to build
Deepen the file-family seam so rooted filesystem access, symlink containment, size limits, atomic replacement, and error semantics have one authoritative implementation. Higher-level APIs should become thin adapters with documented compatibility rather than parallel security-sensitive stacks.

## Blocked by
None — can start immediately.

## Acceptance Criteria

- One rooted filesystem mechanism owns path containment, symlink policy, bounded streaming, and atomic writes.
- Public higher-level read, search, edit, list, and find APIs delegate to that mechanism or document a deliberate semantic difference.
- Equivalent operations use consistent size limits and error classifications.
- Compatibility or deprecation policy is documented for overlapping exported APIs before a stable release.
- Cross-platform and adversarial tests cover traversal, symlink races, oversized files, ignored paths, and atomic replacement.

## Verification Plan

1. Run focused filesystem, fileops, safefs, and fstools tests under the race detector.
2. Run platform build checks for all supported targets.
3. Run the full Go test, vet, lint, and security suites.
