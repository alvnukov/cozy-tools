## Body

## What to build
Give command history one coherent resource-limit contract across index entries, command length, compressed and decompressed records, and configured output limits.

## Blocked by
None — can start immediately.

## Acceptance Criteria

- Index parsing enforces a documented per-entry and total-read bound without allocating an arbitrarily long line.
- Runner policy validation rejects output or command limits that cannot be persisted and read under the record hard cap.
- JSON overhead and duplicated output fields are accounted for so every successfully written record is readable.
- Oversized plain, gzip, index, and command inputs fail with stable actionable errors.
- Existing traversal, symlink, decompression, cleanup, and crash-safety protections remain covered.

## Verification Plan

1. Run focused command history security and lifecycle tests.
2. Run oversized and compressed-input tests with bounded memory expectations.
3. Run the full Go test and race suites.
